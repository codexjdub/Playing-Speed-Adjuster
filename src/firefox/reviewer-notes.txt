BUILD INSTRUCTIONS
The add-on files in dist/firefox/ are generated by build.mjs. psa.js is src/psa.js and src/firefox/page.js joined and wrapped in one function; the other files are copied from src/firefox/ unchanged, and the version is filled into manifest.json. Nothing in the add-on is minified or transpiled. All files in src/ are hand-written.

Build environment: macOS or Linux (tested on macOS and Ubuntu 24.04), with Node.js 20 or later (tested with Node 24) and npm 10 or later.

1. Install Node.js 20 or later from https://nodejs.org/ (npm is included). Check with: node --version
2. Unzip the source package and open a terminal in its folder.
3. Run: npm ci
   (installs the build tool terser and the test tool playwright, as pinned in package-lock.json)
4. Run: npm run build
5. The add-on is now in dist/firefox/, identical to the uploaded package. To compare: unzip the uploaded package into a folder and run diff -r dist/firefox <that folder>

Our GitHub workflow rebuilds on every change and fails if the result differs from the committed files, so the build is reproducible. This version was submitted by that workflow from the matching GitHub release.

WHY THE CODE WORKS THIS WAY
The second content script (psa.js) runs in the page's MAIN world because PSA wraps HTMLMediaElement.prototype.play (to find media that is never added to the page) and, on sites that keep resetting the speed, redefines playbackRate on that media element. Both have to happen in the page's own JavaScript.

bridge.js, in the isolated world, relays JSON-string messages between psa.js and background.js through CustomEvents on the document. background.js keeps settings and positions in storage.local per site (the tab's page origin). A page can only reach its own site's values, and frames embedded from other sites only the speed.

The add-on makes no network requests and collects no data.
